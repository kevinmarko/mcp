# Spec 2.3: "What changed" summary

Status: draft for Kevin, 2026-10-05. Author: R6 (UX). Builder: R1 (only writer of the app HTML).
Plan reference: `docs/ROADMAP_PLAN.md` slice 2.3. Depends on 2.1 (`diffSailings`) and 2.2 (previous-archive-date loader).
Existing pieces this is written against: the banner stack above the masthead (`role="status"` / `role="alert"`
blocks, `{scheduleChangeWarning && ...}`, `{newDataAvailable && ...}`), the Settings popover option rows (Text Size,
Auto-Refresh), `fetchPerDayArchiveIndex` (resolves `null` when the archive cannot be used) and `GOOGLE_SERVICES_OFF`.

## 1. What it is

One short line that answers "what is different from the last day on file?" for the live data: sailings that moved a
lot, sailings that were newly nominated, lanes that went down, and every sailing that was removed. It is a
**separate dismissible banner** (default) or, if the user prefers, a **persistent one-line strip** under the masthead.
It never blocks, never needs a click, and renders nothing when it has nothing true to say.

## 3. Placement

The banners live above the masthead in this order. The new one goes **below the schedule-change warning and above the
historical-viewing banner**, with the same guard those use (`rawRows.length > 0 && !viewingHistoricalDate`).

```
parseError                    red      role=alert
appUpdateAvailable            emerald  role=status
Auto-Refresh OFF              yellow   role=status
autoFetchError / sector...    yellow   role=alert
filterPrefsRestored           slate    role=status
newDataAvailable              blue     role=status      (unchanged)
scheduleChangeWarning         orange   role=alert       (unchanged)
>>> WHAT CHANGED (banner)     teal     role=status      NEW (mode = Banner)
viewingHistoricalDate         indigo   role=status
masthead
>>> WHAT CHANGED (line)       plain text               NEW (mode = Line): its own row between the masthead's
                                                       bottom border and the tab bar. Not inside the masthead's
                                                       right-hand button cluster (see below).
tab bar, filter panel, table
```

Rules that follow from the existing code:

- Problems sit above information, so a warning is never pushed below an FYI line.
- **Never put the line inside the masthead's flex-wrap button cluster.** The 2026-10-02 comment there explains why:
  anything that appears after load wraps the whole cluster and shoves the table down.
- The two teal elements are mutually exclusive (mode is one of Banner, Line, Off). The Line shares the under-masthead slot
  with the worklist bar from spec 3.3 (standing state lives under the masthead, event-style banners above it); Line comes first.
- It mounts once, when the diff is ready, and then updates its text in place. It does not unmount and remount on every
  refresh poll. One layout shift on mount is accepted (every banner here has one); nothing is reserved while loading.
- Both orange and teal can show together. They have different baselines (orange: the previous refresh; teal: the
  previous day), and the teal prefix always names its baseline date, so the overlap in "removed" wording is not
  ambiguous.

## 4. States and exact copy

`{prev}` is the previous *available* archive date rendered `Fri 8/28` (weekday, then month/day, no year). Build it from
the `YYYY-MM-DD` parts with `new Date(y, m - 1, d)`; never `new Date('2026-08-28')`, which is UTC and shows the day
before in US time zones (AGENTS.md check 3). If the gap to today's data date is more than 3 days, append
` (N days earlier)` after the date. The comparison is never "yesterday" and never branches on the weekday: a quiet
weekend simply produces the "no material change" state.

Clauses join with ` · ` (middle dot), in this order, and a clause with a zero count is omitted. Plural rule:
`1 sailing`, `2 sailings`; `1 lane down`, `3 lanes down`.

| ID | Condition | Renders | Copy (exact) |
|---|---|---|---|
| W0 | Mode is Off; basic build (`GOOGLE_SERVICES_OFF`); `fetchPerDayArchiveIndex` returned `null` or the call failed; viewing a historical date; data came from an uploaded file; no rows; the diff threw | **Nothing.** No DOM node, no placeholder, no spinner, no "unavailable" text. In the basic build the Settings control is not rendered either (same as the hidden Export to Drive button). A thrown diff is `console.warn` only. | none |
| W1 | Archive index is a list but has no date earlier than today's data date | Teal banner, no Details button | `No earlier day on file to compare with yet.` |
| W2 | At least one clause other than removed | Teal banner | `Since Fri 8/28: 12 sailings moved 100+ TEU · 2 newly nominated · 1 lane down` |
| W3 | Nothing removed, no moved, no newly nominated, no lane down | Teal banner, no Details button | `No material change since Sat 8/29.` |
| W4 | One or more sailings **removed** (any day, any threshold) | Banner as W2, but the removed clause is first and bold; this state can never be W3 | `Since Fri 8/28: 1 sailing removed (WAHT0613W) · 12 sailings moved 100+ TEU` |
| W5 | Sale-week rollover happened since `{prev}` | Appended as the last, regular-weight clause (W2, W4) or in parentheses (W3) | `... · sale week rolled over: 24 out, 23 in` / `No material change since Sun 8/30 (sale week rolled over: 24 out, 23 in).` |

Removed sailings are **always named**, never only counted: up to three VVDs inline, then `+N more`
(`5 sailings removed (A, B, C, +2 more)`), and all of them in Details. No threshold, no dismissal state and no mode
hides the fact that a sailing disappeared.

Prefix is bold: `Since Fri 8/28:`. The leading emoji (`🔍`) is `aria-hidden`, like the other banners'.
The counts for W5 come from the rolled-in and rolled-out classes of `diffSailings`; the 24 and 23 above are the sailing-level
counts for the 2026-08-30 to 08-31 pair, pinned in tests/check_history_days.js (61 and 58 are the same sailings counted as rows).

## 5. Anatomy and styling (reuses the "New data available" pattern)

Same shape as the blue banner, new hue (teal is unused by every existing banner), so it reads as "briefing", not as a
warning or an update prompt.

```jsx
<div data-what-changed="banner" data-what-changed-state="changes|none|no-previous" role="status"
     className="flex flex-wrap items-center justify-between gap-x-3 gap-y-2 bg-teal-50 dark:bg-teal-950 border border-teal-400 dark:border-teal-700 text-teal-900 dark:text-teal-200 font-semibold px-4 py-2 rounded mb-4 mx-4 shadow-sm text-sm">
  <span className="flex-1 min-w-[14rem]"> <span aria-hidden="true">🔍</span> <b>Since Fri 8/28:</b> ... </span>
  <div className="shrink-0 flex items-center gap-2">
    <button type="button" aria-expanded aria-controls="what-changed-details"
            className="text-xs font-bold text-teal-900 dark:text-teal-100 border border-teal-500 dark:border-teal-600 rounded px-2 py-1 bg-teal-100 dark:bg-teal-900 hover:bg-teal-200 dark:hover:bg-teal-800 cursor-pointer whitespace-nowrap">Details</button>
    <button type="button" aria-label="Dismiss what-changed summary" title="Dismiss (reappears tomorrow, or sooner if another sailing is removed)"
            className="w-6 h-6 rounded-full bg-teal-700 dark:bg-teal-600 text-white text-xs leading-none flex items-center justify-center hover:bg-teal-800 dark:hover:bg-teal-500 cursor-pointer">×</button>
  </div>
</div>
```

- The existing dismiss buttons are `w-5 h-5` (20 px). New one is `w-6 h-6` (24 px, the WCAG 2.2 AA target-size
  minimum). Fixing the older ones is a separate follow-up, not part of this slice.
- Removed clause: `font-bold text-red-800 dark:text-red-300`. The word "removed" carries the meaning; colour only reinforces it.
- Rollover clause and W1/W3 trailing text: `font-normal text-teal-800 dark:text-teal-300`.
- Contrast (computed): teal-900 on teal-50 9.1:1; teal-800 on teal-50 7.3:1; red-800 on teal-50 8.0:1; white on teal-700
  5.5:1; teal-200 on teal-950 11.5:1; teal-300 on teal-950 9.8:1; red-300 on teal-950 7.6:1. All pass AA for text.
- **Line mode** (no box, no dismiss): `<div data-what-changed="line" className="text-xs text-teal-900 dark:text-teal-200 mb-2">`
  with the same text and the same Details button, no `role` (it is persistent, so it is not a live region). W0 still
  renders nothing; W1 renders the W1 copy in `text-gray-500 dark:text-gray-400`.

## 6. Details panel (inline disclosure, not a modal)

Opens directly under the banner or line; `id="what-changed-details"`; `max-h-72 overflow-y-auto`; table wrapper
`overflow-x-auto` so a phone scrolls the table, not the page. Sections appear only when non-empty, in this order, using the
existing "Schedule Change Details" table styling (`text-xs`, `border-gray-300 dark:border-gray-600`, red header band for Removed):

| Section | Columns |
|---|---|
| Removed (n), always first | Lane, Sale Week, VVD, Vessel, Last Cutoff, Last ETD (same columns as the existing removed-sailings table) |
| Moved (n) | VVD, Lane, Laden TEU `prev -> now`, Change (`+120` / `-135`), Utilisation `prev -> now` |
| Newly nominated (n) | VVD, Lane, Sale Week, Vessel |
| Lanes down (n) | Lane, Laden `prev -> now`, Change % |
| Sale-week rollover | One line of counts, no list (`24 out, 23 in`) |

If slice 1.4 ("Show in table") has shipped, the VVD in each row is a button that applies it and leaves the panel open.

## 7. Dismissal, Settings, persistence

- **Dismiss (×)** hides the banner for this combination of previous date, current data date and the sorted list of removed
  VVDs. It comes back automatically the next day, and immediately if a sailing is newly removed (the removed list
  changed). A change in any other count does not bring it back. It does not touch any data.
- **Settings:** one option row, same pattern as Text Size (aria-pressed buttons), label `What changed:` with
  `Banner` / `Line` / `Off`. Hidden entirely in the basic build and when the archive is unavailable. Switching mode clears the dismissal.
- **Storage (local only, every call in try/catch; the page renders correctly with storage blocked):**
  `bookingFlashWhatChangedMode` (`banner|line|off`, default `banner`) and `bookingFlashWhatChangedDismissed`
  (`{prev, cur, sig}`). Both start with `bookingFlash`, so the boot-failure "Reset saved settings" clears them.
- Nothing here is silent state: the banner names its baseline date, and the Settings row shows the mode.

## 8. Keyboard and screen reader

- Tab order: Details, then dismiss. Both are native `<button>`: Enter and Space work, no custom key handling.
- Details: `aria-expanded` true/false, `aria-controls` the panel; label switches between `Details` and `Hide details`.
  Escape inside the open panel closes it and returns focus to the Details button.
- Dismiss: focus must not fall to `<body>`. After dismissing, move focus to the masthead (`tabindex="-1"`, it already has `data-bf-masthead`).
- Banner is `role="status"` (polite), like the blue, slate, emerald and indigo banners. It is not `role="alert"`; that is
  reserved for the orange and red warnings. Late-inserted live regions are announced unreliably in some screen readers,
  so the information must not depend on the announcement: it is also plain text in reading order at the top of the page.
- Line mode has no live region (no chatter on every refresh).
- Visible focus: browser default outline is acceptable; if the app later adds a focus style, use it here.
- No animation, so nothing to switch off for `prefers-reduced-motion`.
- Emoji `aria-hidden`; the removed clause is words, not colour; table headers are real `<th>`.

## 9. Light, dark and 390 px

- Light and dark use the token pairs in section 5; both are in the contrast list above. Details panel: `bg-white dark:bg-gray-800 dark:text-gray-100`.
- 390 px: the banner is 326 px wide (`p-4` root plus `mx-4`), 294 px of text area. `min-w-[14rem]` on the text means the buttons wrap
  under the text at that width and sit beside it from about 430 px up (224 px text + 12 px gap + about 94 px of buttons + 96 px of page and banner padding); no horizontal page scroll (the page must stay at `scrollWidth == innerWidth`). A W4 line wraps to about
  4 lines; that is acceptable and is the reason Details exists. The details table scrolls inside its own wrapper.
- Line mode wraps to at most 2 lines on a phone (`line-clamp-2`), with Details still reachable.
- Verify at 390, 700 and 1366 px, light and dark, in W2, W3 and W4, plus W2 together with the orange warning showing.

## 10. Test hooks and acceptance

- Hooks: `data-what-changed="banner|line"` and `data-what-changed-state="changes|none|no-previous"` (same convention as `data-bf-masthead`).
- Basic build: with `__BF_GOOGLE_SERVICES_OFF__` there is no `[data-what-changed]` node, no Settings row and zero
  `google.script.run` calls (extends `tests/check_basic_build.js`).
- Fixtures (from slice 0.3): the rollover pair renders W3 with the rollover clause (or W2 if a threshold is crossed) and never lists a rolled-out sailing as removed;
  a weekday pair renders W2; a deliberately deleted VVD renders W4 with that VVD named; a single-day archive renders W1.
- Dismiss, then recompute with the same removed list: stays hidden. Add one removed VVD: reappears.
- Row-highlight budget (check 5) is not affected: no row-component props change.

## 11. Out of scope

Per-lane drill-down charts, email (that is the Phase 4 brief), comparing against an arbitrary date (Compare already does that), notification sounds, any threshold editing UI.
