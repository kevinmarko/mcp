# Spec 3.3: Worklist panel

Status: draft for Kevin, 2026-10-05. Author: R6 (UX). Builder: R1 (only writer of the app HTML).
Plan reference: `docs/ROADMAP_PLAN.md` slice 3.3 (also reused by 6.2, the phone Brief view).
Depends on 3.1 (`findExceptions`), 3.2 (config keys), 2.5 (history index). Written against the existing banner and
slicer code: `clearSlicers`, `setSelectedLanes`, `setSelectedSaleWeeks`, `setActiveTab`, `GOOGLE_SERVICES_OFF`.

## 1. What it is

A short list of sailings that need a person: nobody owns them, they have been over their threshold for several days
with time still to fix it, or they are nominated but have no cut-off date. It is **collapsed by default**, shows a
**count badge**, and every row is a **click-through** that filters the table to that sailing. If there is nothing to
list it **renders nothing at all**.

## 2. Decisions needed from Kevin

| # | Question | Recommendation (what this spec assumes) |
|---|---|---|
| K1 | Default on or off? | **On, collapsed.** Costs one 36 px bar on days there is something to see, nothing otherwise. Until calibration (slice 3.4) the list may be noisy, which is why it is collapsed and why Settings can switch it off. |
| K2 | What does "N days" count? | Consecutive **archive days including today**, not calendar days (a weekend with no archive file is not counted). N is D3's value (start at 3) from the config Sheet. Needs 3.1 to say the same. |
| K3 | Over-threshold row: what is "threshold"? | Blocked on D2 (meaning of `MCT Loading Threshold` / `MCT Overall Threshold`; the values vary per row, see D2 in the plan). Until answered the row carries no figure, only the days and lead time. Once D2 is answered add a third fragment such as `127% vs 120%`. |
| K4 | Does "nominated sailing without a cut-off date" carry a day count? | No (3.1 rule (c) has no persistence). Say so if you want one. |
| K5 | Scope: all sailings, or only mine? | **All** (the list ignores the slicers, so a filter can never hide a problem). "Mine only" needs D4 (name to email mapping) and belongs with slice 4.5. |
| K6 | Click-through: replace the current filters, or add to them? | **Replace**: clear the slicers, then select that sailing's lane and sale week. Adding would often produce an empty table (e.g. SPC PIC = Evan active, item belongs to Ryan), which looks like a bug. |
| K7 | Sort and grouping | Groups in this order: Over threshold, Unowned, No cut-off date. Inside a group: most days first, then shortest lead time, then VVD. Say if you would rather lead with Unowned. |
| K8 | Snooze or acknowledge a row? | **No** in v1. Risk: a known-unfixable item reappears daily and the panel gets ignored. Lanes where blank PIC is normal are already excluded by config (D4). Revisit with the 3.4 calibration numbers. |
| K9 | History unavailable (basic build, archive or history index down): show only the one rule that needs no history (no cut-off)? | **No, render nothing.** A partial list reads as "no unowned sailings" when we simply could not tell. |

## 3. Placement

Standing state (it is there most days) sits **under the masthead, above the tab bar**, so it never shoves the masthead,
logo and Refresh/Settings buttons down (the banners above the masthead already do that when they appear). It shares that
slot with the 2.3 "Line" mode, which comes first.

```
banners (event-style, above masthead)         unchanged
masthead                                       unchanged
[2.3 what-changed line, if mode = Line]
[3.3 worklist bar / panel]      <- NEW: no mx-4 (aligns with the masthead), mb-2
tab bar, filter panel, table
```

Renders on every tab (the list is about sailings, not about one tab). Not rendered while `viewingHistoricalDate` is set
(the list describes live data), when there are no rows, or when the Settings toggle is off.

## 4. States

| ID | Condition | Renders |
|---|---|---|
| L0 | Items = 0; or history/archive unavailable; or basic build; or historical date; or no rows; or toggle off; or computing threw | **Nothing.** No bar, no "All clear", no placeholder. A thrown computation is `console.warn` only. |
| L1 | Items >= 1, collapsed (the load default) | One bar: `▸ Worklist [7]  3 over threshold · 3 unowned · 1 no cut-off date` |
| L2 | Items >= 1, expanded | Bar (`▾`) plus the grouped list |

Count badge: total items, `99+` above 99. The per-kind preview is hidden below 640 px (`hidden sm:inline`) and omits
kinds with zero items.

## 5. Row copy (exact)

Line 1 is bold: `{VVD} · {Lane} · {Sale week}` (sale week as the table shows it, e.g. `2026/W29`).
Line 2 is the reason, muted:

| Kind | Group heading | Line 2 |
|---|---|---|
| `over_threshold` | `Over threshold (3)` | `Over threshold for 5 days (lead time 14 days)`; lead time 1: `(lead time 1 day)`; lead time 0: `(cut-off today)` |
| `unowned` | `Unowned (3)` | `Unowned for 4 days`; one day: `Unowned for 1 day` |
| `no_cutoff` | `No cut-off date (1)` | `Nominated sailing without a cut-off date` |

Examples on the 9-day data (plan 3.1): `WAHT0613W`, `HTET1002W` and `GJMT0003W` are the three unowned sailings the fixture
test must reproduce. This assumes 3.1 leaves out sailings already past cut-off (laden freezes after cut-off, so there is nothing left to manage), so a negative lead time never appears; R2 to confirm.
The vessel name goes in the row's `title` attribute only (not visible on touch screens, so nothing depends on it).

Footer line inside the expanded panel (always, so the scope is never a silent assumption):
`All lanes and sale weeks, whatever the filters say. Lanes configured as "blank PIC is normal" are left out.`

## 6. Anatomy and styling

Neutral card (the list is a tool, not a warning), with the app's existing amber count pill (the `⚙ Fields  8 hidden`
pill: `bg-[#ffc000] text-black`).

```jsx
<section data-worklist="" aria-label="Worklist" className="bg-white dark:bg-gray-800 border border-gray-400 dark:border-gray-600 rounded mb-2 shadow-sm text-sm text-gray-900 dark:text-gray-100">
  <button type="button" aria-expanded={open} aria-controls="worklist-panel"
          aria-label="Worklist, 7 items: 3 over threshold, 3 unowned, 1 without a cut-off date"
          className="w-full min-h-[44px] sm:min-h-[36px] flex items-center gap-2 px-4 py-2 text-left font-bold hover:bg-gray-100 dark:hover:bg-gray-700 cursor-pointer">
    <span aria-hidden="true">{open ? '▾' : '▸'}</span><span>Worklist</span>
    <span aria-hidden="true" className="px-2 py-0.5 rounded-full bg-[#ffc000] text-black text-xs">7</span>
    <span className="hidden sm:inline ml-2 font-normal text-xs text-gray-600 dark:text-gray-300">3 over threshold · 3 unowned · 1 no cut-off date</span>
  </button>
  {open && (
    <div id="worklist-panel" className="border-t border-gray-300 dark:border-gray-600 max-h-[60vh] overflow-y-auto">
      <h3 className="px-4 pt-2 pb-1 text-xs font-bold uppercase tracking-wide text-gray-700 dark:text-gray-200">Over threshold (3)</h3>
      <ul>
        <li><button type="button" className="w-full text-left px-4 py-2 min-h-[44px] border-t border-gray-200 dark:border-gray-700 hover:bg-gray-100 dark:hover:bg-gray-700 cursor-pointer">
              <div className="font-bold">WAHT0613W · WAH · 2026/W29</div>
              <div className="text-xs text-gray-600 dark:text-gray-300">Over threshold for 5 days (lead time 14 days)</div>
              <span className="sr-only">. Show in table</span></button></li>
      </ul>
      <p className="px-4 py-2 text-[11px] text-gray-500 dark:text-gray-400 border-t border-gray-200 dark:border-gray-700">All lanes and sale weeks, ...</p>
    </div>
  )}
</section>
```

- No scroll-hiding: the list scrolls inside `max-h-[60vh]`, every item is reachable, the badge shows the true total.
- Contrast (computed): gray-600 on white 7.6:1; gray-300 on gray-800 10.0:1; gray-500 on white 4.8:1; gray-400 on gray-800 5.8:1; black on `#ffc000` above 12:1.
- **Class-list collisions with the regression suite.** The suite finds elements by class substrings. This spec avoids
  `w-[44px]` (Lane buttons are found with it), the pair `text-[11px]` + `font-bold` with a `W\d+` text (sale-week chips),
  `bg-gray-300`, `bg-red-600`, `bg-[#eef2fa]`, and `aria-pressed` on anything outside the Settings popover (the baseline
  step waits for no `button[aria-pressed="true"]`). R1 must grep `tests/booking_flash_regression_tests.js` for
  `className.includes` and `aria-pressed` before finalising class names.

## 7. Interaction

**Bar click:** toggles open. Open state is not saved: every page load starts collapsed. When data refreshes the panel updates
in place and stays open; it never steals focus; if the focused row disappears, focus moves to the bar button.

**Row click (click-through):**
1. If the active tab is not Booking Flash (`detail`) or POL Booking Flash (`pol_booking`), switch to `detail`.
2. `clearSlicers()`, then `setSelectedLanes([lane])` and `setSelectedSaleWeeks([saleWeek])`. Lane plus sale week identifies
   one sailing in both tables. This differs from slice 1.4 ("Show in table"), which since 2026-10-06 keeps the reader's other
   slicers and sets only the Lane (or Yard) slicer, leaving Sale Week alone: a row click names one sailing, a lane card does not.
   The VVD column filter (`handleHeaderFilterChange('vvd', ...)`) is deliberately **not** used: it is a text box inside
   a column header of a 3,652 px wide table, which on a phone is scrolled out of sight, so the filter would be easy to
   miss (silent state). Pressed slicer chips are the app's main visible filter state.
3. If the filter panel is collapsed (Hide Filters), expand it so the applied slicers are visible.
4. Collapse the worklist, scroll the table into view, move focus to the table container (`tabindex="-1"`).
5. Polite status text inside the section (visually hidden, always mounted while the panel renders):
   `Showing WAHT0613W: lane WAH, sale week 2026/W29.`
6. The slicers are saved like any other slicer change, so the next visit shows the existing "Your filters from last time were restored" banner. That is existing behaviour, not new state.

If the lane and sale week hold more than one VVD, the table shows all of them; acceptable.

**Settings:** an On/Off button in the Settings popover, same pattern as Auto-Refresh and Freeze Panes
(`Worklist: On`), key `bookingFlashWorklist` (`'1'`/`'0'`, default `'1'`), local only, every storage call in try/catch.
Hidden entirely in the basic build.

## 8. Keyboard and screen reader

- Tab order: bar button, then each row button in list order, then on to the tab bar. Native buttons: Enter and Space work.
- Escape inside the open panel collapses it and returns focus to the bar button (also the way out of a long list without tabbing through it).
- `aria-expanded` and `aria-controls` on the bar; its `aria-label` carries the total and the per-kind breakdown, and the visible
  badge is `aria-hidden` so nothing is read twice.
- Groups are `<h3>` + `<ul>`; each row reads as VVD, lane, sale week, reason, "Show in table".
- No live region for the count (it would chatter on every refresh). The single polite status is the click-through message above.
- Colour is never the only signal: group headings and reasons are words.
- No animation.

## 9. Light, dark and 390 px

- Light and dark classes as in section 6; the amber pill is the same in both themes, as it is on the Fields button.
- 390 px: bar is 358 px wide (`p-4` root, no `mx-4`), preview text hidden, bar and rows are at least 44 px tall,
  reason text wraps (no truncation), panel capped at 60 vh and scrolls inside itself, the page does not scroll
  sideways. The bar adds 44 px plus 8 px margin above the tab bar on days it shows.
- 6.2 (phone Brief view) should reuse this component with a `defaultOpen` prop rather than a copy.
- Verify at 390, 700 and 1366 px, light and dark, in L1 and L2, including a long list (20+ rows) and the L0 case (no node in the DOM).

## 10. Test hooks and acceptance

- Hooks: `data-worklist` on the section, `data-worklist-kind="over_threshold|unowned|no_cutoff"` on each row button.
- L0: with no exceptions, or `__BF_GOOGLE_SERVICES_OFF__`, `document.querySelector('[data-worklist]')` is null.
- Fixtures: the 9-day set yields exactly the three unowned sailings above at N = 3; a flat-threshold rule (613 rows) must not appear.
- Click-through: after clicking a row, the pressed slicers are exactly that lane and sale week, every other slicer is cleared,
  the table shows only that sailing's rows, the worklist is collapsed, and (from Trade Summary) the active tab became Booking Flash.
- Row-highlight budget (check 5) is not affected: no row-component props change.

## 11. Out of scope

Snooze, assign, notes from the row, "mine only", email (Phase 4 brief), editing thresholds in the UI, sorting controls.
